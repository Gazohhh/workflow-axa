Reference

Context and scope

You agreed to revision r1 on 2026-11-11, and to the changes of revision r2 the same day.

You saw every workflow-axa skill twice, for the second time. Two copies can differ, and then two sessions give different results.

You asked for a check that finds a second copy and asks you to delete it.

Goals and non-goals

Agreed behavior

At session start the plugin looks for a second copy of its skills in your personal skills folder and in the project.

If it finds one, the agent names the exact paths and asks you to delete them. The guard deletes nothing.

Until the copies are gone, the skills that change a project do not load. Read-only work continues. Your words "continue with duplicates" lift the pause for one session.

Not included: Codex, old plugin cache versions, the 17 broken links and the five review findings.

The design

Overview

One new hook script does all of it. It reads the skill names from the plugin's own list, so there is no second list to maintain.

The script runs at three moments: when a session starts, when a skill is loaded, and when you send a message. The existing approval hook is not changed.

A defect in the guard must never block work. On bad input the script allows the action and prints nothing.

  • The five review findings are a separate second task.

Alternatives considered

  • You chose to build on top of the staged rc.35 work, over committing it first.
  • You chose to delete the duplicate links and keep the plugin, over deleting nothing.
  • You chose to pause change work with an override, over a warning only and over blocking everything.
  • You chose that only a message that is exactly the words lifts the pause, over the words anywhere in a message.
  • You chose to keep version 2.8.0-rc.35, over rc.36, which needed files outside the approved list.
  • The agent removed 6 more duplicate links than the 15 you approved, because its first count was cut off (D3).
  • The agent set the override to end after 12 hours and made the guard stop a typed change command. You answered "sure fix it" to both (D13). The agent reads that as agreement.
  • Three more agent choices were shown to you and not answered one by one. Parent folders are checked. The request warns about links. A temp folder that cannot hold the marker lets work continue.

Cross-cutting concerns

  • Without Python no hook runs, so the guard does not run. Codex has no hooks, so the guard does not run there.
  • No check ran in a live session. The message shown for a stopped typed command is not seen on a host.
  • A typed bare duplicate name such as /tdd is not stopped. Only the three change commands are.
  • When the guard stops a typed command, the two other hooks on that message still run. The approval gate may then treat the session as a workflow session.
  • The rules comparison reads only the first START.md import in the global CLAUDE.md.
  • An agent could create the override marker with a shell command. A wrong WORKFLOW_AXA_GATE_CACHE value switches the pause off.
  • Four defects remain and need a small plan for revision r2.
  • Defect 1: one sentence in SETUP.md and in the CHANGELOG says a typed bare duplicate name is stopped. That is untrue.
  • Defect 2: a read-only temp folder keeps the pause, against ticket T2.
  • Defect 3: no test asserts that the existing hook registrations are unchanged.
  • Defect 4: on resume the start message says "paused" while an override is active.
