Technical details

What you approve

The owner agreed to the behavior in agreement r1 on 2026-11-11.

What was asked

You saw every workflow-axa skill twice, for the second time. Two copies can differ, and then two sessions give different results.

You asked for a check that finds a second copy and asks you to delete it.

What will happen

At session start the plugin looks for a second copy of its skills in your personal skills folder and in the project.

If it finds one, the agent names the exact paths and asks you to delete them. The guard deletes nothing.

Until the copies are gone, the skills that change a project do not load. Read-only work continues. Your words "continue with duplicates" lift the pause for one session.

Not included: Codex, old plugin cache versions, the 17 broken links and the five review findings.

Decisions made

You chose to build on top of the staged rc.35 work and to delete the duplicate links. You chose to pause change work with a one-session override. The five review findings become a second task.

The agent removed 6 more links of the same kind than the 15 you approved, because its first count was cut off. This is recorded as D3.

What stays the same

  • hooks/phase_gate.py and both approval gates stay as they are.
  • The folder ~/.agents/skills stays, because Codex and the global rules import use it.
  • The 18 staged rc.35 files stay staged. This work adds to them and reverts none.
  • No Codex support, no cleanup of old plugin cache versions, no repair of the 17 broken links.
  • The five review findings are a separate second task.

The work

Approach

One new hook script does all of it. It reads the skill names from the plugin's own list, so there is no second list to maintain.

The script runs at three moments: when a session starts, when a skill is loaded, and when you send a message. The existing approval hook is not changed.

A defect in the guard must never block work. On bad input the script allows the action and prints nothing.

Ticket T1Planned

Find duplicate copies at session start and ask the owner to delete them

Add hooks/duplicate_skills.py. At session start it looks in the personal skills folder and in the project's .claude/skills for a name the plugin registers. It also compares the imported rules copy with the plugin's rules.

Expected result

A duplicate is reported with its full path and the request to delete it. Equal bytes are still reported. No duplicate gives no output. A broken link is not reported. The script changes no file.

Depends on
Nothing. It can start first.
How it is checked
  • Run tests/test_duplicate_skills_hook.py with a temporary home.
  • The hook test compares the file list and bytes before and after.
  • Run the hook test with a changed rules file.

Ticket T2Planned

Pause change work while duplicates exist, with a one-session override

Extend the same script. When a change skill is loaded and a duplicate exists, it refuses. A user message with "continue with duplicates" stores an override for that session.

Expected result

workflow-clarify, workflow-specify and workflow-execute are refused with the paths and both ways out. task-status and workflow-doctor load. After deletion the next call is allowed without a restart. The override holds for one session only.

Depends on
T1 Find duplicate copies at session start and ask the owner to delete them
How it is checked
  • Run the hook test with PreToolUse events.
  • Run the hook test with UserPromptSubmit and PreToolUse events for two session IDs.
  • The hook test compares the file list and bytes before and after.
