Context and scope

You agreed to the r2 additions on 2026-11-11, together with the plan.

The guard is delivered, and you saw it work in live sessions: the start note, the stop of a typed command, and the override.

The reviews and the reconciliation left four small defects. In your live check the agent also added "deliver" to the paused skills by itself.

You said "plan r2". This plan repairs the four defects and makes the messages name the three paused skills.

Goals and non-goals

Goals

  • Both guard messages name the three paused skills.
  • The start note tells the truth when your override is active.
  • The docs say only what the guard does.
  • A test fails when a later edit changes the registration of another hook.

Non-goals

  • Stopping a typed bare duplicate name such as /tdd. It stays a named limit.
  • Making a temp folder that refuses writes lift the pause. The docs name it as a limit.
  • A check that an agent-made skill call is refused in a live session.

The design

Overview

The start note asks the same question the refusal already asks: is the pause lifted for this session? If yes, it says so. The paths and the request to delete stay in both cases.

The list of the three skills comes from the one list the script already has, so the messages and the check cannot drift apart.

The new test holds the expected commands of every other hook, per event and in order. It reads hooks/hooks.json and changes nothing.

Constraints

  • What is paused and how the override works stay as they are.
  • hooks/phase_gate.py and hooks/hooks.json stay as they are.
  • The version stays 2.8.0-rc.35.
  • The staged rc.35 edits in SETUP.md and CHANGELOG.md stay. This work adds to them.

Alternatives considered

  • A temp folder that refuses writes: the plan names it as a limit in the docs. Not chosen: a write probe on every refused call, because it adds file writes to a check that must stay read-only.
  • Pinning the other hooks: the plan uses a list of expected commands in the test. Not chosen: a comparison with the last commit, because a test must not depend on the state of Git.
  • You chose "plan r2" over leaving the four defects (D14).

Cross-cutting concerns

  • The r2 repairs were not seen in a live session. You can repeat your earlier check.
  • The pinning test does not notice an extra key that is added to an existing hook entry.
  • A refused bare duplicate name gets a reason that names the three change skills and not that name.
  • The limits of the first delivery stand: no Python means no guard, Codex has no hooks, and a typed bare duplicate name is not stopped.
