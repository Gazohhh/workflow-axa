Reference

Context and scope

You agreed to the behavior in agreement r1 on 2026-11-11.

You saw every workflow-axa skill twice, for the second time. Two copies can differ, and then two sessions give different results.

You asked for a check that finds a second copy and asks you to delete it.

Goals and non-goals

Goals

  • Find a second copy of any workflow-axa skill at every session start.
  • Name the exact paths and ask you to delete them.
  • Hold the skills that change a project until the copies are gone. Read-only work continues.
  • Let you lift the pause for one session with the words "continue with duplicates".
  • Warn when the imported rules copy differs from the rules of the plugin.

Non-goals

  • Deleting a copy automatically. The guard deletes nothing.
  • Codex support. Codex has no hooks.
  • Cleanup of old versions in the plugin cache.
  • Repair of the 17 broken links.
  • The five review findings. They are a separate second task.

The design

Overview

One new hook script does all of it. It reads the skill names from the plugin's own list, so there is no second list to maintain.

The script runs at three moments: when a session starts, when a skill is loaded, and when you send a message. The existing approval hook is not changed.

A defect in the guard must never block work. On bad input the script allows the action and prints nothing.

Constraints

  • hooks/phase_gate.py and both approval gates stay as they are.
  • The folder ~/.agents/skills stays, because Codex and the global rules import use it.
  • The 18 staged rc.35 files stay staged. This work adds to them and reverts none.

Alternatives considered

  • Build on top of the staged rc.35 work and leave it staged. Not chosen: commit rc.35 first, which publishes an unfinished release under this task.
  • Delete the duplicate links and keep the plugin and ~/.agents/skills. Not chosen: delete nothing, which keeps every skill listed twice.
  • The agent removed 6 more links of the same kind than the 15 you approved, because its first count was cut off. Leaving them kept the duplicate you asked to remove. This is decision D3.
  • The guard asks and pauses change work, with a one-session override. Not chosen: warn only, because the agent could still load the wrong copy unnoticed. Not chosen: block all workflow use, because one stale link could stop urgent work.
  • The guard is a new script. Not chosen: change hooks/phase_gate.py, because that file carries open approval defects you asked not to touch.
  • The guard reads the skill names from plugin.json. Not chosen: a fixed list of names in the script, because plugin.json already is that list.

Cross-cutting concerns

  • Without Python no hook runs, so the guard does not run. Codex has no hooks, so the guard does not run there.
  • The tests run the script with test events. They cannot show how a real Claude Code session displays the message. You check that after you install rc.36.

The work

The implementation plan: 3 tickets, built after you approve. They are built in this order. Each starts when the one before is verified.

How it is tested

Each behavior gets a test first. The tests run the script as a process with a temporary home folder, and compare that folder before and after.

The full existing suite runs before the first change and after the last one. The two results must be equal, apart from the new tests.
