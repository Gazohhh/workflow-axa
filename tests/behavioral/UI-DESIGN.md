# UI-design acceptance suite

These are authored cases, not live-model results. Run ui-design.json against the baseline and candidate in disposable projects with identical host/model, permissions, stack versions and Matt specialists. Include Claude and Codex, ordinary prompts without slash commands, explicit workflow, resumed sessions and delegated workers. Record actual loaded rules/skills, prompts/replies, diffs, preview exposure, verification and reported completion. Do not show expected outcomes to the agent.

UI01–UI32 cover missing/approved kits, functionality-only fallback, preview isolation, legacy and utility classes, visual props, CSS-in-JS, canvas/native/Unity, accessible controls, narrow repairs, existing styling, design authoring, report exceptions, scope/version changes, old tasks, output truthfulness and incomplete scanners. No case is passed because the agent repeats the rules. Inspect changed files and relevant rendered states. A correct stop for a missing material decision is success; repeatedly blocking an already-approved ordinary step is not.

Reuse each fixture's existing plan/output locations; no report or build per question. Keep only needed evidence, protect user edits and reset only disposable fixtures. In real projects, a release check is not permission to publish or expose unfinished UI. Rules/setup approval remains separate from application/design approval.

The optional diff scanner is deliberately triage-only. Its automated tests exercise cues and malformed inputs; this suite tests whether the agent interprets them correctly. Its exit code 0 never grants policy compliance or design acceptance.
