# Shared design-review rules, not a shared visual theme

Identify the project's approved design system, components, state/interaction patterns, accessibility expectations, responsive targets and reference images. Reuse them. Keep a workflow report's editorial style separate from the application's appearance; do not impose one typography, palette or layout on all projects.

When a material appearance/interaction decision is missing, ask before inventing it. Do not block a backend-only task on unrelated visual rules. Explain the user outcome before filenames. Compare changed screens under controlled viewport, data, font and browser conditions, then check meaning, keyboard navigation and relevant UI states. A matching screenshot is not proof of functional correctness or universal pixel equality.

Keep accepted references immutable unless the user approves replacement; do not update them merely to turn a failed comparison green. Retain only necessary comparison evidence under the artifact policy. This module adds no aesthetic choices and does not replace local codebase-map/FLOWCHART-DESIGN.md.
