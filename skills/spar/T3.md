# Debaters and their briefs

Read by `/spar` on every run. Parts marked T3 Code apply only where its tools exist.

## Who debates

**T3 Code.** Call `orchestrator_capabilities` once, before the start card. Its list is short: before you conclude a model is missing, look it up with its `search` (or its omitted models). Two debaters run:

- **GPT** through `delegate_task` with the provider that lists it (such as `codex`);
- **a fresh Claude** through `delegate_task` with the `claudeAgent` provider, not the host's own subagent tool, so both debaters run side by side in the background.

On the start card, offer a recommended pair from two different makers among the models listed, or the owner chooses A and B. Name the exact model of each in the frame line. When no cross-maker pair can run, the card's debater field offers the menu below instead; no separate question.

**GPT not listed, Claude not runnable (not listed, or its launch failed), or the check failed**: say which, and ask the owner how to proceed with the menu below. A failed check is a failure, never "GPT absent". Never substitute a model on your own.

## When a debater can't run

One menu, before the openings and when a debater fails later. Always offer every choice that can still run:

- **Relaunch the failed debater** for this round (after the openings only).
- **A fresh Claude through the host's own subagent** (Claude hosts only), with GPT through `delegate_task`, when only the `claudeAgent` route can't run: still cross-model.
- **Two fresh helpers** of a model that still runs (in T3 Code, `delegate_task` with that provider), labelled "single model, fresh context, not cross-model" in the frame line, every progress line and SPAR.md.
- **Spar with me only**: the owner and you spar. You write the options, then attack your own recommendation, labelled as self-critique. It is never called cross-model. In this mode the frame names <A> vs <B> as "you vs me" and the launch limit as 0; effort and cap don't apply; it is never "agreed", only a labelled recommendation.
- **End sparring**: cancel any debater still running; show the partial conclusion, then the handoff question (SKILL.md section 5). It is not a cancel.
- **Try again later**: cancel any debater still running; tell the owner to rerun `/spar`.

After either ending choice, a result that arrives later is ignored.

**Without T3 Code** (no `delegate_task`, as in the Claude Code CLI or Codex): ask the owner with the same menu on the start card. Two helpers run through the host's own subagent tool, one after the other when it can't run them side by side; the "single model, fresh context, not cross-model" label applies, and the host's own way to stop a helper replaces `task_cancel`. With no subagent tool at all, only **Spar with me only** remains.

## Launching and waiting

- Every launch is a fresh context, so every brief is complete on its own.
- Text written before tool calls may reach the owner only as a summary. In T3 Code, send the frame line with `send_to_user` before the first `delegate_task`; that is the only time it is shown, unless the idea or the debaters change. Elsewhere, write it as the turn's first text, before the first launch. A safety notice and the conclusion go out the same way.
- **T3 Code:** one `delegate_task` per debater per round. Send both briefs for the round. Then end your turn; a debater's completion wakes you. Never poll. When one debater returns, note its position in the conversation and end your turn again.
- **Without T3 Code:** run both helpers, in parallel when the host can, else one after the other. Then collect both results the way that tool returns them.
- **Mixed** (a fresh Claude through the host's subagent, GPT through `delegate_task`): launch GPT first. Then run the helper. Then end your turn until GPT returns.
- On every host: act on a round only when both have returned.
- A debater that fails: keep what it already returned, and use the menu above with the launches left. A retry or replacement never uses the last two launches of a cap unless the owner raises it. A replacement debater judges the current text itself; an earlier acceptance doesn't carry over.
- On a cancel, call `task_cancel` (T3 Code) for every running debater; a result that arrives later is ignored.
- Debaters only read and return findings: they write no records and change no files.

## The opening brief

```text
Spar about <the idea in one sentence>; opening; you are debater <A|B>.
Role: an independent debater. Read only what a claim needs. Write nothing. Start no agents.
Justified disagreement is success; a changed position needs its reason.
Intent and success criteria: <from SPAR.md>
Owner decisions so far: <short list>
Evidence: <fact (source) | assumption | contradiction (evidence)>
Return, in about 500 words: your recommendation and why; challenge the framing (doing nothing, a simpler way,
whether the need is real); the options you rejected and why; your strongest uncertainty; points only the owner
can decide; anything you could not check.
```

## The exchange brief

```text
Spar about <the idea>; exchange <n> of <budget or cap>; you are debater <A|B>.
Role: an independent debater. Read only what a claim needs. Write nothing. Start no agents.
Justified disagreement is success; a changed position needs its reason.
Intent and success criteria: <from SPAR.md>
Owner decisions so far: <short list; new ones marked>
Evidence: <with changes marked>
Your last position <id>: <in full>
Other side's last position <id>: <in full>
The disagreements that could change the outcome: <short list, each with its evidence so far>
Return, in about 500 words: your answer on each listed disagreement, with evidence; your new position (or your
last one unchanged, with why); your verdict on each current proposal, by its id (accept or reject, with the
reason; an accept with amendments is a reject); points only the owner can decide; anything you could not check.
```

## The synthesis brief

```text
Spar about <the idea>; synthesis check; you are debater <A|B>.
Role: an independent debater. Read only what a claim needs. Write nothing. Start no agents.
Justified disagreement is success; a changed position needs its reason.
Intent and success criteria: <from SPAR.md>
Owner decisions so far: <short list>
Coordinator's synthesis <id>: <in full>
Return, in about 300 words: accept it as written, or reject it, with reasons and remaining blockers. An accept with amendments is a reject;
name the amendment you would need. Write no new position.
```
